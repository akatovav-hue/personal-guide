### Эволюция гипотезы в слоте (главный продукт)

**На входе:** зона → обязательство (прецедент юристов: зона «юр. безопасность» → обязательство, не список договоров).

**На выходе:** **потребности организации → роли → маппинг текущих → gap → новые зоны → обязательство** (6-звенная цепочка).

Добавилось:
- **Upstream «зоны»** — её источник (потребности организации), не назначение sponsor'ом.
- **Метод выявления gap** — интервью с коллегами: что они считают своей зоной = какие роли уже несут без выделения новых обязанностей.
- **Различение role / position** — одна должность может нести несколько ролей. Ирина так делает с новыми должностями (Финпартнёр, рук. ВЭД укрупнённый — позиции, в которые она кладёт несколько ролей).

### Объяснение прострации 25-27.04 (bonus)

Найдено прямо в слоте: причина прострации не в дефекте дисциплины и не в недостатке Self-Diag Gate. Причина — **отсутствие upstream-формулировки СВОЕЙ зоны ОД** через 6-звенную цепочку. Без зоны нет фильтра «моё / не моё», поэтому РП подхватываются по чужим намерениям.

Self-Diag Gate (S-16, 27.04) был ответом на симптом. Теперь видна причина — нужна upstream-формулировка зоны через цепочку.

### Финальная формулировка вопроса к Лапутину #5

> Лапутин, проверь гипотезу о формировании зоны ответственности у роли:
>
> **Цепочка:**
> 1. Потребности организации (для функционирования нужны роли: привлечение клиентов / производство / финансы / cross-cutting координация / развитие / ...) →
> 2. Набор необходимых ролей →
> 3. Маппинг текущих исполняемых (через интервью с коллегами — что они считают своей зоной) →
> 4. Gap = необходимые роли, никем не исполняемые →
> 5. Формулировка новых зон под gap →
> 6. Обозначение зоны автоматически налагает обязательство на носителя (прецедент юристов).
>
> **Применительно к роли ОД:** моя текущая работа (3-step function L4.6: детектор → преобразователь → контролёр) — это шаги 3-5 цепочки для cross-cutting проблем. Прострация 25-27.04 объясняется тем, что **СВОЯ зона ОД** ещё не сформулирована через эту цепочку.
>
> **Вопрос:** цепочка «потребности → роли → зона → обязательство» — правильный upstream для функционального определения роли, или нужен иной механизм?

### Что НЕ задаём этой формулировкой (повестка на следующие слоты)

- Технику маппинга (как именно интервьюировать) — уровень практики.
- 3-step vs 4 типа решений как decomposition — растворяется (обе оси про одну зону).
- Калибровку K1-K4 — после подтверждения upstream.
- ОД↔Владимир (DEC.3) — частный случай Ирининых новых должностей.
- L4.7 эскалация vs role-reassertion — после подтверждения механизма зоны.

### Тест функционального места

«Другой носитель занимает место ОД и читает формулировку — он понимает обязательство?» — ДА, через цепочку «зона ← роль ← потребность», которая обещает быть переносимой между носителями.
